# AI Text Polisher — Feature Specification

## Overview

AI Text Polisher 是一个纯前端单页 Web 应用，帮助用户通过 DeepSeek AI 对文本进行场景化润色改写。用户粘贴原文、选择润色场景、点击按钮，即可在右侧获得改写结果并一键复制。

**范围**：仅文本润色，无登录、无持久化存储、无多页面路由。

---

## Functional Requirements

### FR-01 文本输入

- 用户可在页面左侧文本区域粘贴或输入待润色文本
- 文本长度上限为 **3000 字**（前端校验，超出时禁用润色按钮并给出提示）
- 文本区域实时显示当前字符数 / 3000，便于用户感知限制
- 输入区域支持多行，并可自由调整高度（或固定高度可滚动）

### FR-02 场景选择

- 页面顶部展示 6 个场景预设，用户每次只能选中一个（单选）
- 默认选中第一个场景（**学术润色**）
- 6 个场景定义如下：

| 场景 Key | 显示名称 | 润色目标 |
|----------|----------|----------|
| `academic` | 学术润色 | 正式学术语气，去除口语化表达，保持原意 |
| `business_email` | 商务邮件 | 专业商务语气，结构清晰，含开头问候与结尾礼貌用语 |
| `social_media` | 社交媒体 | 轻松活泼，可含 emoji，输出控制在 280 字以内 |
| `tech_doc` | 技术文档 | 术语精确，偏好被动语态，步骤编号，代码格式保留 |
| `creative` | 创意写作 | 文学性表达，使用比喻、排比、拟人等修辞 |
| `translation` | 翻译优化 | 中文输入→地道英文；英文输入→流畅中文；不逐字硬翻 |

### FR-03 润色操作

- 页面包含「润色」按钮，点击触发 DeepSeek API 调用
- 按钮在以下情况下禁用：
  - 输入文本为空
  - 输入文本超过 3000 字
  - 正在请求中（loading 状态）
- 点击后按钮变为不可交互，显示加载状态

### FR-04 加载状态

- API 请求进行中，右侧结果区域显示加载提示（如"润色中..."）
- 加载提示需有明确的视觉标识（文字 + 动画指示器，如旋转图标或省略号动效）
- 整个请求期间用户无法再次点击润色按钮

### FR-05 结果展示

- API 响应成功后，右侧区域展示润色后的文本
- 结果文本区域只读，不可编辑
- 结果区域支持多行滚动，完整展示全部内容

### FR-06 一键复制

- 结果区域提供「复制」按钮
- 点击后将结果文本写入系统剪贴板
- 复制成功后按钮临时显示"已复制 ✓"，约 2 秒后恢复原文字
- 仅在有润色结果时按钮可用

### FR-07 错误处理

- API 调用失败（网络错误、非 2xx 响应、超时等）时，右侧区域展示友好错误提示
- 提示语言清晰，不直接暴露原始错误信息（如 HTTP 状态码或堆栈）
- 示例提示："润色失败，请检查网络后重试" / "服务暂时不可用，请稍后再试"
- 错误状态下复制按钮不可用

### FR-08 输入清空 / 重置

- 提供「清空」按钮（或输入框内置清空图标），可清除输入文本
- 清空输入后，结果区域同步清空
- 场景选择不随清空操作重置（保持用户上次选择）

## User Scenarios

### Scenario A：学术用户润色论文段落

1. 打开页面，默认已选中"学术润色"
2. 在左侧粘贴一段 800 字的论文草稿
3. 点击「润色」
4. 右侧显示"润色中..."动画
5. 约 5–10 秒后，右侧显示正式学术风格的改写版本
6. 用户点击「复制」，按钮变为"已复制 ✓"
7. 用户将文本粘贴进论文编辑器

### Scenario B：切换场景重新润色

1. 用户已有一段润色结果（学术）
2. 点击顶部"社交媒体"场景
3. 点击「润色」按钮
4. 右侧刷新为社交媒体风格结果

### Scenario C：超字数输入

1. 用户粘贴超过 3000 字的文本
2. 字符计数器变红，「润色」按钮禁用
3. 用户删减文本至 3000 字以内，按钮重新可用

### Scenario D：API 出错

1. 用户点击「润色」
2. 网络请求失败（或 API Key 无效）
3. 右侧显示友好错误提示，无原始错误堆栈

## Success Criteria

| # | 验收标准 | 可测试方式 |
|---|----------|------------|
| SC-01 | 6 个场景均可选中，且同时只有一个选中 | 手动点击各场景按钮，检查选中状态 |
| SC-02 | 输入超过 3000 字时润色按钮禁用 | 粘贴超长文本，验证按钮状态 |
| SC-03 | 点击润色后显示加载提示，请求完成后消失 | 点击润色，观察 UI 状态变化 |
| SC-04 | 润色结果在右侧正确展示 | 输入已知文本，验证结果非空且合理 |
| SC-05 | 复制按钮将结果写入剪贴板 | 点击复制后粘贴至其他位置验证内容一致 |
| SC-06 | API 失败时显示友好错误提示，不显示原始错误 | 断网或使用无效 Key 触发失败 |
| SC-07 | 清空按钮清除输入与结果，不重置场景选择 | 操作后验证各区域状态 |
| SC-08 | API Key 从环境变量读取，源码中无硬编码 Key | 代码审查 + grep 检查 |
| SC-09 | 无任何 CSS 框架依赖（仅 Tailwind） | 检查 package.json dependencies |
| SC-10 | TypeScript 严格模式编译无错误 | `tsc --noEmit` 通过 |

## Non-Goals（明确不做）

- 用户账号 / 登录 / 注册
- 润色历史记录持久化
- 多页面 / 路由
- 服务端渲染（SSR）
- 移动端专项适配（响应式布局友好即可，不做原生 App）
- 批量处理多段文本

---

## Technical Constraints（来自 Constitution）

- React 19 + TypeScript strict + Vite + Tailwind CSS v4
- 目录结构：`src/components/` `src/api/` `src/config/` `src/types/`
- DeepSeek 模型：`deepseek-chat`
- Vite proxy：`/api/*` → `https://api.deepseek.com/*`
- API Key：`VITE_DEEPSEEK_API_KEY` 环境变量
- 禁止 any、禁止路由库、禁止外部状态管理库
